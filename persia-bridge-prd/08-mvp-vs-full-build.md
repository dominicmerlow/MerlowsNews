# Part 08 — MVP Scope vs Full Build Scope

**Platform:** Persia Bridge | **Brand:** The Cyrus Accord
**Version:** 1.0 | **Date:** March 2026

---

## 1. Scope Philosophy

The MVP exists to serve one goal: **get the founding 12 Cyrus Fellows and first 300 Achaemenid Members onto the platform, building real relationships and real deals.**

Everything in the MVP must earn its inclusion. If a feature does not directly serve onboarding, trust-building, or deal formation for the founding cohort, it is deferred. Every module built in MVP is designed to compose cleanly into the Full Build — nothing is thrown away.

**MVP window:** 6 months from green light to founding cohort launch.
**Full Build window:** Months 7–36, phased with membership growth.

## 3. MVP Build Sequence

The recommended build order balances: trust infrastructure first, then community, then commerce.

```
Sprint 1–3 (Weeks 1–6): Foundation
  ├── Auth (magic link, password, email OTP)
  ├── Member profile + application flow
  ├── Admin: application review queue + member management
  ├── Role system + RBAC middleware
  └── Basic audit log

Sprint 4–6 (Weeks 7–12): Community Layer
  ├── Member Directory (search, filters, profiles)
  ├── Connection system
  ├── Direct messaging
  ├── Notifications (in-app + email)
  └── Chapter Hub (3 founding chapters, events, RSVP)

Sprint 7–9 (Weeks 13–18): Content Layer
  ├── The Chronicle (CMS, publishing, reading experience)
  ├── Knowledge Base (upload, browse, viewer)
  ├── Heritage Layer (onboarding journey, cultural guides, language resources)
  └── Email digest

Sprint 10–12 (Weeks 19–24): Commerce Layer
  ├── KYC/KYB integration (Persona)
  ├── Bazaar (listings, moderation, enquiry flow, Stripe Connect)
  ├── Deal Room (submission, NDA e-sign, data room, IOI)
  ├── Syndicate Engine (create, room, discussion, votes)
  └── Sanctions screening (ComplyAdvantage)

Sprint 13–14 (Weeks 25–28): Launch Prep
  ├── QA + accessibility audit (WCAG 2.1 AA)
  ├── Security review + penetration testing
  ├── Performance audit (Core Web Vitals)
  ├── GDPR compliance review
  ├── Legal review (NDA templates, Bazaar terms, investor T&Cs)
  └── Founding cohort onboarding (soft launch with 12 Cyrus Fellows)
```

## 4. Deferred but Architected

These features are explicitly out of MVP scope but the architecture must not block them:

| Feature | Why Architected Now |
|---------|-------------------|
| RTL (Farsi/Hebrew) | CSS logical properties from day one; retrofitting RTL is expensive |
| Native mobile apps | React + Next.js is the right foundation; no web-specific coupling in UI logic |
| Elasticsearch/Typesense | PostgreSQL full-text search with correct indexes; migration path is clean |
| AI matching | No ML-specific infrastructure needed; add embeddings + pgvector column later |
| Escrow payments | Stripe Connect already integrated for Bazaar Phase 1; Phase 2 adds escrow flow |
| SPV document templates | Document storage and e-signature infrastructure in place from Deal Room |
| Video content | Supabase Storage supports video; streaming CDN (Cloudflare Stream) added when needed |
| Multi-currency | Currency field on all financial models from day one |

## 6. Technical Debt Register (Accepted for MVP)

These are known shortcuts accepted for MVP speed, with a clear plan to resolve:

| Shortcut | Accepted Risk | Resolution Target |
|----------|--------------|-------------------|
| No real-time messaging (polling every 30s) | Slightly delayed messages | Replace with Supabase Realtime in Month 4 |
| PostgreSQL full-text search only | Less sophisticated search UX | Migrate to Typesense at 5,000+ members |
| Manual PDF watermarking (member name in filename, not burned in) | Lower security for deal docs | Server-side watermarking in Full Build |
| No application-level encryption for deal room docs | Signed URLs provide access control; no extra encryption layer | Add at scale when institutional investors require it |
| Email-only notifications (no push) | Lower engagement on mobile | PWA push in Month 6; native app push in Year 2 |
| Admin panel as internal routes (not separate subdomain) | Acceptable for MVP; IP restriction in place | Move to `admin.persiabridge.com` with separate auth in Month 6 |
| No automated re-screening of sanctions lists | Initial screen only | Quarterly re-screen job in Month 3 |
